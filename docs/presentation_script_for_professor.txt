1. OPENING (30–45 seconds)
--------------------------
MAIN SCRIPT:
"Thank you for your time. I built a small project that tries to predict how much 
Actinium-225 you could get from irradiating Radium-226 in a neutron field — the 
Ra-226 to Ra-225 to Ac-225 chain. Instead of running a full differential-equation 
solver every time, I trained a physics-informed neural network — a PINN — to 
approximate those dynamics quickly, then wrapped it in a website so you can change 
flux, time, and energy and see inventories update in real time."

[SIDENOTE: "differential equations" = math rules for how amounts change smoothly 
over time, like 'how fast Ra-226 goes down' written as dN/dt.]

[SIDENOTE: "neutron field / flux" = how many neutrons pass through an area per 
second; more flux usually drives more transmutation reactions.]

[SIDENOTE: "PINN" = Physics-Informed Neural Network: a neural net that is trained 
not only to match data but also to respect physics equations (here, decay and 
production terms).]


2. WHY Ac-225 MATTERS (45–60 seconds)
-------------------------------------
MAIN SCRIPT:
"Ac-225 is interesting for targeted alpha therapy — attaching it to molecules that 
seek tumors. Supply is limited relative to clinical interest. Production involves 
planning irradiations, which is expensive. If engineers could sweep many scenarios 
of flux, time, and neutron energy quickly, they could compare schedules without 
waiting on a heavy simulation every time. That was my motivation."

[SIDENOTE: "targeted alpha therapy" = treatment where a radioactive atom that 
emits alpha particles is delivered mainly to cancer cells.]

[SIDENOTE: "transmutation" = one nucleus changing into another via reactions or 
decay (here, neutron reactions plus radioactive decay).]


3. PHYSICS BASELINE (60–90 seconds) — speak carefully; professor will listen here
---------------------------------------------------------------------------------
MAIN SCRIPT:
"I treated the problem with a compact Bateman-style system: Ra-226 can transmute 
under flux with an effective production path toward Ra-225; Ra-225 beta-decays 
to Ac-225; Ac-225 decays. Half-lives and the chain structure come from standard 
nuclear data references in the code, similar in spirit to NNDC values. The 
'ground truth' for training is generated by numerically integrating those ODEs 
with SciPy — essentially an ODE solver stepping the inventories through time."

[SIDENOTE: "Bateman equations" = classic math for a chain of isotopes where each 
decays or feeds the next; named after work on radioactive chains.]

[SIDENOTE: "ODE" = Ordinary Differential Equation — here, rates of change of atom 
numbers vs time.]

[SIDENOTE: "numerically integrating" = using a computer to approximate the 
solution curve step-by-step instead of solving by hand.]

OPTIONAL IF ASKED about cross sections:
"The code uses a schematic thermal cross section and scales it with neutron energy 
using a one-over-v — 1/v — style ratio from a thermal reference, which is a 
standard first approximation, not a full evaluated cross-section library."

[SIDENOTE: "cross section" = effective probability/size for a nuclear reaction 
with a neutron, often in barns.]

[SIDENOTE: "1/v law" = at low energy, many reaction rates drop roughly like 
1/sqrt(energy); the code encodes that shape in the PINN inputs.]


4. THE NEURAL NETWORK IDEA (60–90 seconds)
------------------------------------------
MAIN SCRIPT:
"The PINN is a multilayer perceptron — a feedforward neural network — with a 
hard constraint so that at time zero the predicted inventories match the initial 
condition. During training I combine two pressures: fit the ODE-generated 
trajectory data, and penalize violation of the same differential relations the 
solver uses — that's the physics loss. I also enforce practical constraints: 
non-negative inventories, a mass budget so the model cannot invent atoms from 
nothing, and penalties inspired by secular equilibrium ideas for the daughters."

[SIDENOTE: "multilayer perceptron / MLP" = stack of layers that transform numbers; 
the basic 'vanilla' neural network.]

[SIDENOTE: "feedforward" = data flows one direction: inputs → hidden layers → 
outputs, no loops inside the net.]

[SIDENOTE: "physics loss" = extra error terms that push the network to satisfy 
equations, not only mimic data.]

[SIDENOTE: "secular equilibrium" = after enough time, parent and daughter activities 
can settle into a fixed ratio if the chain allows; the code uses a ceiling idea 
so Ac-225 does not blow past a physically plausible transient cap.]


5. TRAINING PIPELINE (45–60 seconds)
------------------------------------
MAIN SCRIPT:
"Training runs in two phases in my script: a physics-heavy pretrain on collocation 
points — random samples in time, flux, energy, and sometimes empty initial 
inventories — then joint training that adds supervised error against CSV samples 
from the ODE. I used Adam optimization with learning-rate reduction on plateau, 
gradient clipping for stability, and species-weighted data terms so Ra-225 and 
Ac-225 are not drowned out by the huge Ra-226 scale. Total training is on the 
order of twelve thousand epochs in the full configuration."

[SIDENOTE: "collocation points" = random or chosen input points where you check that 
the physics equations are satisfied, even without a measured label there.]

[SIDENOTE: "Adam" = a standard adaptive optimizer for training neural networks.]

[SIDENOTE: "gradient clipping" = limit how big an update step can be so training 
does not explode numerically.]

[SIDENOTE: "epoch" = one full pass through the training schedule / dataset logic; 
not always 'every row once' in PINNs, but 'one training iteration cycle'.]


6. SOFTWARE / CODING SIDE (45 seconds)
--------------------------------------
MAIN SCRIPT:
"I implemented the model in PyTorch, the ODE reference in Python with SciPy, and 
the demo as a Streamlit app. The app loads trained weights, runs forward passes for 
live sliders, includes a small benchmark comparing PINN throughput to repeated 
ODE solves, and optional upload-based fine-tuning on CSV measurements — a simple 
transfer-learning style adaptation of the last layers."

[SIDENOTE: "PyTorch" = library for tensors and automatic differentiation; standard 
for research-style deep learning.]

[SIDENOTE: "Streamlit" = Python framework to build interactive web dashboards 
quickly.]

[SIDENOTE: "transfer learning" = start from weights trained on one task and adapt 
a small part of the model to new data.]


7. VALIDATION (30 seconds)
--------------------------
MAIN SCRIPT:
"I document three sanity tests: empty initial inventory with high flux should stay 
zero — no 'alchemy'; a fueled case should track the ODE within a stated tolerance; 
and a decay-only case with no flux should not create Ra-226 from nothing. These 
are not a substitute for full reactor validation, but they catch gross unphysical 
behavior."

[SIDENOTE: "sanity test" = a simple check that the model is not doing something 
obviously impossible.]


8. LIMITATIONS & HONEST CLOSE (45 seconds)
------------------------------------------
MAIN SCRIPT:
"This is a student prototype. It uses simplified nuclear data and reaction 
modeling compared to production codes like ORIGEN or MCNP-linked burnup. The PINN 
is a surrogate — fast but dependent on the training distribution. I would expect 
a professor to critique the cross-section treatment, the completeness of the 
chain, and whether uncertainties are quantified. My goal was to combine correct 
structure — Bateman dynamics plus constraints — with a fast evaluator and a clear 
interface."

[SIDENOTE: "surrogate model" = a fast approximate replacement for a slower 
'high-fidelity' simulation.]

[SIDENOTE: "ORIGEN / MCNP" = industry-style codes for transmutation and transport; 
much heavier than my project.]
